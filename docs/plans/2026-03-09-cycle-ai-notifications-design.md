# Cycle AI Notifications — Design Doc

Date: 2026-03-09
Platform: Android
Branch: android-nikhil

## Overview

Replace static hardcoded cycle notification strings with AI-generated, personalized messages. Two delivery paths:

1. **Daily phase tips** — on-device, generated fresh each morning using the user's current cycle state and logged symptoms/mood
2. **Event alerts** — server-side, generated by a Supabase Edge Function for period-approaching and ovulation-day events, delivered by the existing `AiNudgeWorker`

## Architecture

```
DAILY PHASE TIPS (on-device)
CycleNotificationScheduler
  └── schedules CycleAINudgeWorker via WorkManager (daily 8 AM)
        └── fetches cycle data from MenstrualCycleRepository
        └── calls AIService → ai-router (Supabase edge function)
        └── shows notification on CHANNEL_CYCLE
        └── fallback: static message if AI fails

EVENT ALERTS (server-side)
Supabase cron: cycle-ai-nudges edge function (daily 7 AM UTC)
  └── queries users: period in 2 days OR ovulation today
  └── fetches recent menstrual_daily_logs for context
  └── calls ai-router with full cycle context
  └── inserts row into ai_nudges table
        └── AiNudgeWorker (runs every 30 min) delivers via CHANNEL_AI_NUDGE
```

## Notification Types

### Daily Phase Tip
- **Title**: `"Today's Cycle Tip"` (fixed)
- **Channel**: `CHANNEL_CYCLE`
- **Trigger**: 8 AM daily via WorkManager `PeriodicWorkRequestBuilder`
- **Tag**: `"cycle_ai_nudge_daily"` for cancellation/rescheduling

### Period Approaching Alert
- **Title**: `"Period Approaching"` (fixed)
- **Channel**: `CHANNEL_AI_NUDGE`
- **Trigger**: Server-side, when period is 2 days away
- **Dedup key**: `nudge_type="cycle_period" + user_id + date`

### Ovulation Day Alert
- **Title**: `"Ovulation Day"` (fixed)
- **Channel**: `CHANNEL_AI_NUDGE`
- **Trigger**: Server-side, on predicted ovulation date
- **Dedup key**: `nudge_type="cycle_ovulation" + user_id + date`

## Prompt Design

### Daily Phase Tip Prompt
```
You are a women's health assistant. Write a warm, personalized daily health tip
as a push notification (max 2 sentences, actionable).

Cycle context:
- Phase: {phase} (Day {dayInCycle} of {totalDays})
- Days until next period: {daysUntilPeriod}
- Logged symptoms today: {symptoms or "none logged"}
- Mood: {mood or "not logged"} | Pain level: {painLevel}/10
- Fertile window: {yes/no} | Cycle regularity: {regularity}

Reply with only the notification message.
```

### Period Approaching Prompt
```
You are a women's health assistant. Write a compassionate period reminder
as a push notification (max 2 sentences, include one practical tip).

Context:
- Period expected in: 2 days
- Commonly logged symptoms: {top symptoms from recent logs}
- Average pain level: {avgPain}/10 | Cycle regularity: {regularity}

Reply with only the notification message.
```

### Ovulation Day Prompt
```
You are a women's health assistant. Write an informative ovulation day reminder
as a push notification (max 2 sentences, supportive tone).

Context:
- Today is the predicted ovulation day
- Fertile window: {fertileWindowStart} to {fertileWindowEnd}
- Cycle regularity: {regularity}

Reply with only the notification message.
```

## Cycle Context Data (Full)

Both on-device and server-side prompts include:
- Current cycle phase
- Day in cycle / total cycle length
- Days until next period
- Recently logged symptoms (from `menstrual_daily_logs`, last 3 days)
- Mood and pain level (most recent log)
- Whether in fertile window
- Cycle regularity (Regular / Somewhat Irregular / Irregular)

## Error Handling

### CycleAINudgeWorker
- AI call fails → falls back to static message (current `CycleNotificationScheduler` strings) → `Result.success()`
- Network unavailable → `Result.retry()` with exponential backoff
- No cycle data found → skip notification, `Result.success()`

### cycle-ai-nudges Edge Function
- `ai-router` fails for a user → log error, skip that user, continue to next
- User already has undelivered nudge of same type today → skip (dedup)
- DB query fails → return 500, Supabase retries on next cron tick

## WorkManager Configuration

```kotlin
PeriodicWorkRequestBuilder<CycleAINudgeWorker>(24, TimeUnit.HOURS)
    .setInitialDelay(/* time until 8 AM */)
    .setConstraints(Constraints.Builder()
        .setRequiredNetworkType(NetworkType.CONNECTED)
        .build())
    .setBackoffCriteria(BackoffPolicy.EXPONENTIAL, 5, TimeUnit.MINUTES)
    .addTag("cycle_ai_nudge_daily")
    .build()
```

## Supabase Edge Function Cron

In `supabase/config.toml`:
```toml
[functions.cycle-ai-nudges]
schedule = "0 7 * * *"  # daily 7 AM UTC
```

## Notification IDs

Reuse existing constants from `NotificationService`:
- Daily tip: `NOTIF_CYCLE_LOG` (3003) — replaces the static daily log reminder
- Event alerts: `NOTIF_AI_NUDGE_BASE + hash(nudge.id)` — handled by `AiNudgeWorker`
